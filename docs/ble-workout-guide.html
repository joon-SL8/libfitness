2. Integration Roadmap

2.1 Discovery Phase

Discovery is managed by BluetoothSearchService. It filters for fitness equipment and maintains a list of discovered sensors.

val bleService = AppComponent.get<BluetoothSearchService>()

// Observe state
bleService.scanDeviceState.collect { /* update UI */ }

// Start scanning
bleService.startScanning()

2.2 Connection Phase

Establish a GATT connection to the selected device. The library automatically wraps the connection in the appropriate sensor class (e.g., BikeTrainerSensor).

// Initiate connection
bleService.connectToDevice(selectedDevice)

Library Improvement: Automatic Registration

The DataCollectionService now automatically synchronizes with connected sensors upon starting a session. Manual addCollector() calls are only needed for custom or virtual sensors.

2.3 Workout Setup

Configure the session with an MRC course. The library will handle connecting the dots between the timer and the hardware.

val session = AppComponent.get<DataCollectionService>()
val course = MrcParser.parse(mrcContent)

// session.addCollector(...) is now OPTIONAL for connected BLE sensors
session.beginSession(course)

3. Architecture Best Practices

We recommend the Orchestrator Pattern using a ViewModel to manage the lifecycle and state transitions cleanly.

class WorkoutViewModel : ViewModel() {
    private val bleService = AppComponent.get<BluetoothSearchService>()
    private val sessionService = AppComponent.get<DataCollectionService>()

    fun onSensorSelected(device: BluetoothComponent) {
        viewModelScope.launch {
            bleService.connectToDevice(device)
            // No need to manually add collector; handled by beginSession()
        }
    }

    fun startWorkout(mrcFile: String) {
        val course = MrcParser.parse(mrcFile)
        sessionService.beginSession(course)
        
        viewModelScope.launch {
            sessionService.collect().collect { /* Update UI State */ }
        }
    }
}
